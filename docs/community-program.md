# Community Contribution Program

## Monthly Rule Sprint

Each month we run a **Rule Sprint** — a focused effort where contributors collaborate to close detection gaps. Sprints are announced in Discussions and tracked via the `community:sprint` label.

- Sprint duration: 1st–28th of each month
- Theme announced on the 1st (e.g., "Initial Access techniques", "Linux coverage")
- Participants submit PRs tagged with `community:sprint`
- Results summarized in a monthly wrap-up post

## Good-First-Rule Criteria

Issues labeled `good-first-rule` are ideal for newcomers. They must meet ALL of:

- Single technique/sub-technique with clear documentation
- Public log samples or test data available
- No complex correlation or stateful logic required
- Existing similar rule to use as a template

## Recognition

- **CHANGELOG**: Every merged rule credits the author by GitHub handle.
- **README**: Top 10 all-time contributors listed in the Contributors section.
- **Release Notes**: Sprint winners highlighted in each monthly release.

## How to Participate

1. Check open issues with `good-first-rule` or `community:sprint` labels.
2. Comment on the issue to claim it.
3. Submit a PR following the [contribution guide](../CONTRIBUTING.md).
4. Respond to review feedback.
5. Get merged and earn your badge!
